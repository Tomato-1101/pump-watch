## 0. 結論（先にここだけ読む）

**推奨: 「多時間軸バースト検出 × 3 種の相対正規化 × 加算スコア × 通知予算」に置き換える。主役はチェーンレーン。**

1. **判定の主役をチェーンレーン（生取引 5 分 deque・2 秒 judge）に移す**。API レーンは DexScreener の 30 秒キャッシュ＋20 秒周期で
   **構造的に 30〜60 秒遅れる**ので、価格・出来高・買い手の「上抜け」はチェーンから出す。API レーンは holders / smart / visiting /
   流動性 といった「文脈値」の供給役に格下げする（既に `augment()` がその形になっている）。
2. **固定閾値を捨て、各指標を「驚き（surprise）」に変換する**。短窓の件数 k を長窓から出した期待値 μ と比べる
   ポアソン対数尤度比 `G = sqrt(2·(k·ln(k/μ) − (k − μ)))` を z 値として使う。同じ「15 秒で買い手 3 人」でも、
   死んでいた銘柄なら G≈4.3（大事件）、毎分 4 人来ている銘柄なら G≈1.6（何でもない）になる（§5.4）。
3. **正規化は 3 系統を併用する**: (a) 自己ベースライン（同一銘柄の 30 分・24 時間）、(b) 規模ベースライン（流動性帯ごとの
   母集団分位。実測表 §1.3）、(c) 物理制約（定積 AMM の価格インパクト ≈ 出来高/流動性）。新規銘柄には (a) が無いので
   **同齢コホート分位**（同じ launchpad・同じ経過分数の全銘柄と比べる）を使う。
4. **スコア S = 4·Burst + 2·Breadth + 2·Pressure + 1.5·Accel + Context − Penalty**（§5.1）。Burst は 15 秒/60 秒/5 分の
   買い手・出来高サプライズの上位 2 つの平均。Context に **自前スマートマネー名簿の即時照合**（GMGN を待たない）を入れる。
5. （旧）**段階（小・中・やばい）は絶対しきい値でなく「通知予算」で決める** → §11 で 4 レベル固定カットに変更。予算は「満点の物差し」の較正に使う: 小は 1 時間 12 件まで、中は 1 日 15 件、やばいは 1 日 3 件を
   スコア順に採用。市場が全体に沸いても静かでも通知量が要件（小は多く・大きいは少なく）に固定される（§5.2）。

**実測が示す現行ルールの問題（§1.4）**: 旧ルールで【やばい】が出た BSC 銘柄 14 件のうち、1 分バケットで買い手・出来高の
バーストが観測できた 9〜10 件では、**バーストは発火の中央 12〜13 分前に既に起きていた**（測定窓 15 分の上限で打ち切りなので
実際はもっと前の可能性がある）。固定閾値（例: S3 の買い手 150 人）は「もう上がった後」を撃っている。

**次の一手**: §8 の変更を入れて **シャドー運用（通知せず `scores` に記録）を 3〜7 日** → §9 のリプレイで段階しきい値を
予算から逆算 → 切替。実装は別タスク（Tomato の GO 後）。

## 2. 設計原則

1. **速さは「窓の短さ × 証拠の最小量」で決まる**。最短窓は 15 秒（EMA なら τ=10 秒）、最小証拠は「ユニーク買い手 3 人」。
   それ以下は統計的にノイズと区別できない。5 秒窓は「点火」の補助（次の判定を待たずに即評価する trigger）として使う。
2. **価格を主軸にしない**。価格は出来高・買い手の結果。ただし「出来高のわりに価格が動かない」＝ wash/往復 の検出には使う。
3. **絶対値は最終ゲートだけ**（最小流動性・最小出来高・honeypot 除外）。判定はすべて相対（自己・帯・物理）。
4. **段階は分位と予算で決める**。通知量を固定し、しきい値は毎日データから逆算する。
5. **一度出した段階は昇格しか通知しない**（ヒステリシス）。降格・横ばいは沈黙。

## 3. 特徴量カタログ（計算式つき。★＝チェーンレーンで即時、☆＝API レーンで数分遅れ）

### 3.1 到着率・バースト（多時間軸）★

- **硬い窓の件数**: 窓 w ∈ {15s, 60s, 300s} の 買い件数 B_w、ユニーク買い手 U_w、買い USD V_w、売り USD S_w（deque から）。
- **EMA カウンタ（窓不要・1 取引 O(1)）**: `N_τ ← N_τ · exp(−Δt/τ) + 1`、到着率 `r_τ = N_τ/τ`。τ ∈ {10s, 60s, 300s, 1800s}。
  Hawkes の励起項 Σ e^{−β(t−t_i)} と同じ量（β = 1/τ）。
- **ポアソン・サプライズ**（推奨の中核）: 短窓の件数 k、期待値 μ = 長窓の率 × 短窓長（floor 付き）。
  `LLR = k·ln(k/μ) − (k − μ)`（k > μ のとき、else 0）、`G = sqrt(2·LLR)`（Wilks で z 相当）。
  長窓は「自己 30 分（直近 2 分を除く）」と「自己 24 時間」の 2 本。μ の floor は `1/長窓長` と帯 p50 の大きい方。
- **短/長 EMA 比**: `R = r_60 / r_1800`。Hawkes の分岐比の代理 `n̂ ≈ 1 − r_1800 / r_60`（1 に近いほど臨界＝連鎖）。
- **加速度**: `Accel = max(0, G_60(t) − G_60(t − 30s))`（30 秒前の値を保持するだけ）。
- **CUSUM（率の変化点）**: `g ← max(0, g + x·ln(λ1/λ0) − (λ1 − λ0)·Δt)`、λ0 = 自己 24h 率、λ1 = 3·λ0、警報 g > h。
  サプライズと違い「じわじわ増える」を拾う。

### 3.2 広がり（買い手の質）★

- **ユニーク比** `U = U_300 / B_300`（1 に近いほど分散、0.3 未満は 1 人連打）。
- **新規買い手率** `F_new = |買い手 ∩ 過去 24h 未出現| / U_300`（銘柄ごとに 24h 買い手集合を保持。上限 2,000 件で打ち切り）。
- **集中度** `Top1 = 最大買い手の買い USD / V_300`、`Top3` も。0.5 超は「大口 1 発」でバーストと区別。
- **ブロック分散**: 1 ブロックに ≥ 5 の異なる買い手（特に最初の 3 ブロック）＝ bundle/sniper、連続ブロックに 1〜2 人ずつ＝ organic。
- **往復率** `RT = |売り手 ∩ 直近 5 分の買い手| / U_300`（買ってすぐ売る）。

### 3.3 圧力（買い圧・価格インパクト整合）★

- **買い圧** `BSI_w = (V_w − S_w) / (V_w + S_w)`（USD 版）と件数版。取引 5 件未満なら無効。Order Flow Imbalance の AMM 版。
- **価格インパクト整合** ρ: 定積 AMM で純買い V_net が入ったときの理論値 `Δp/p = (1 + 2·V_net/L)² − 1`（L = プールの USD 流動性。
  小さいときは ≈ 4·V_net/L）。観測 Δp/p との比 `ρ = 観測 / 理論`。ρ ≪ 1 → 往復・複数プール・wash、ρ ≫ 1 → 流動性が抜けている。
  V3（集中流動性）や集約ルーターでずれるので **ソフトなペナルティにだけ使う**。

### 3.4 規模の正規化（流動性・時価総額）

- **帯別分位テーブル**（§6.1）: 流動性帯 × 指標（buyers5m, buys5m, vol5m, V/L, buyers/分）× 分位（p50/p75/p90/p95/p99/p99.9）を
  **毎日 23:00 の digest ジョブで再計算**して `bands` に保存。指標を帯内パーセンタイル P に変換し、`Φ⁻¹(P)` で z にする
  （p90→1.28、p99→2.33、p99.9→3.09）。
- **物理正規化** `V/L`: 規模非依存。「5 分で流動性の 2% の純買い」は帯を問わず ≈ 8% の値動き圧力。
- **mcap/liq**: 高いほど少額で動く。価格系特徴の重み `w_price = clip(100 / (mcap/liq), 0.3, 1)`（§6.3）。

### 3.5 文脈（API レーン）☆ と 自前スマートマネー名簿 ★

- ☆ holders の 30 分増分率、smart/renowned の 30 分増分、visiting の 30 分比、GeckoTerminal trending 順位の 5 分改善幅。
  90 秒スナップショットなので **確認（Context）にしか使わない**。
- ★ **自前名簿の即時照合**: 別途集めた「成績の良いウォレット」（数百〜数千件）を
  チェーンレーンに常駐ロードし、`trader` が名簿にあれば **ブロック時刻で** +2/件（上限 +6）。10 分以内に 3 件以上＝
  クラスタ流入で即「中」。GMGN の smart カウントを数分待つ必要がなくなる。名簿は週 1 で `portfolio profits` から更新。

### 3.6 ライフサイクル別（新規・既存・再燃）

| 種別 | 定義 | ベースライン | 追加特徴 |
|---|---|---|---|
| 新規 | 最初の取引から 60 分未満 | **同齢コホート**: 同じ launchpad（four.meme / Pancake 直 / Pons）で過去 7 日に出た全銘柄の、同じ経過分数 a における累積 U と V の分位 | four.meme は bonding curve の進捗速度（BNB/分。卒業 ≈ 18 BNB）の分位。ブロック分散（bundle 検出）を強く効かせる |
| 既存 | 60 分以上、直近 24h に活動あり | 自己 30 分・24h | 通常のサプライズ |
| 再燃 | 直近 24h の率が 7 日平均より低い「静寂」からのバースト | 自己 24h と **7 日**（1 分バケットを 1 時間に丸めて 7 日保持） | 静寂比 `Q = r_300 / max(r_24h, floor)`、holders の絶対数（燃料）、前回バーストからの日数 |

### 3.7 市場全体の補正（マーケットファクター）★

チェーン全体のユニーク買い手/分（全銘柄合計）の robust z を `z_m(t)` とし、各銘柄の G から `κ·max(0, z_m)`（κ=0.5）を引く。
BSC 全体が沸いている時間帯に全銘柄が同時に鳴るのを防ぐ（株の β 調整と同じ発想）。

### 3.8 ペナルティ（wash / bot / 崩れ）★☆

| U < 0.3（1 人連打） | −3 |
| Top1 > 0.5 | −2 |
| bundle（最初の 3 ブロックに同ブロック ≥ 5 買い手） | −2 |

### 3.9 追加のアイデア（安価に足せる順）

- **テーマ熱**: 直近 30 分に同じ/類似シンボルの新規銘柄が何件出たか（`chain_tokens.symbol`）。クローン量産はテーマが沸いている証拠。
- **卒業イベント**: four.meme の migrate（PancakeSwap プール生成）直後 3 分を独立コホートとして評価（移行直後は流動性が急に厚くなる）。
- **創設者の履歴**: dev ウォレットの過去打ち上げの ATH（GMGN dev エンドポイント）を新規銘柄の事前確率に（遅いのでバッチで）。
- **【推測】メムプール**: pending tx を見れば 1〜3 秒早いが、公開 RPC では取れないことが多い。対象外。
- **SNS**: PumpSense 型（Telegram/X）は遅く有料。対象外。

## 4. スコア方式の候補と比較

| 案 | 中身 | 捉えるもの | 速さ | 実装 | 誤検知耐性 | 判定 |
|---|---|---|---|---|---|---|
| **A 加算サプライズ**（推奨） | 各特徴を z（G）にして重み付き和。§5 | 多時間軸の上抜け＋広がり＋圧力 | 2〜5 秒 | 小（math だけ） | 中（ペナルティ併用で高） | **本命** |

## 5. 推奨案（A + B + H）の具体

### 5.1 スコア式

各成分は 0〜6 にクリップした z 相当。

```
Burst    = mean(top2 of { G_U15, G_U60, G_U300, G_V60, G_V300 })
           G_U*: ユニーク買い手のサプライズ（自己 30 分 / 24h の大きい方の長窓で μ を出し、小さい方の G を採用 = 保守的）
           G_V*: 買い USD の robust z（log(1+V) の median/MAD、MAD floor 0.5）
Breadth  = clip(Φ⁻¹(P_U300), 0, 6) + 2·F_new          （P_U300 = 帯内パーセンタイル。新規は同齢コホート）
Pressure = 6·max(BSI_60, 0)·min(1, B_60/5) · w_price
Accel    = clip(G_U60(t) − G_U60(t−30s), 0, 6)
Context  = min(6, 2·n_listed_10m + [Δsmart_30m ≥ 2] + [Δholders_30m ≥ 15%] + [visiting_30m 比 ≥ 2] + [GT rank 5 分で 20 位改善])
Penalty  = §3.8 の合計
S        = 4·Burst + 2·Breadth + 2·Pressure + 1.5·Accel + Context − Penalty     （上限 ≈ 63）
```

重みは事前分布（priors）。§9 のシャドー運用で「発火後 30 分の最大上昇率」に対する各成分の単独 AUC を見て調整する。

### 5.2 段階・予算・クールダウン

| 段階 | 暫定条件（シャドーで分位に置換） | 予算（H） | クールダウン | 昇格 |
|---|---|---|---|---|
| 小（watch） | S ≥ 14 かつ U_60 ≥ 3 かつ liquidity ≥ $20K | 1 時間 12 件（S 順） | 銘柄あたり 30 分 | — |
| 中（hot） | S ≥ 22 かつ U_300 ≥ 帯 p90 かつ vol5m ≥ max($5K, 0.02·L) | 1 日 15 件 | 2 時間 | 小→中は即時 |
| やばい | S ≥ 32 かつ vol5m ≥ max($50K, 0.10·L) かつ U_300 ≥ 帯 p99 かつ U ≥ 0.5 かつ not wash | 1 日 3 件 | 6 時間 | 中→やばいは即時 |

- 予算を超えたぶんは通知せず `scores` に記録（`/near` の後継 `/score` で見る）。予算が 3 日連続で余る/溢れるときは、
  しきい値をその段階の直近 7 日分位（小 p90 / 中 p99 / やばい p99.9）に自動で寄せる。
- 同じ段階の再通知はクールダウン内なら **S が前回通知の 1.5 倍以上**のときだけ。
- Kleinberg 型の状態（B）を段階の裏に置く: quiet→burst の遷移でだけ「小」を出し、burst 継続中は S の伸びだけ見る。

`w_price = clip(100 / (mcap/liq), 0.3, 1)`。mcap/liq が 100 の銘柄は 1.0、1,000 なら 0.3（帯 p99 は 200〜8,600 なので、
小型帯の裾は価格をほぼ信用しない）。Pressure と、必要なら pc5m 由来の特徴に掛ける。

### 6.4 最小規模ゲートの再設計

- 現行 `size_any`（mcap ≥ $100K or vol24h ≥ $300K or vol5m ≥ $30K）は「もう大きいもの」しか通さず、初動と矛盾する。
  **判定前ゲートは liquidity ≥ $20K と honeypot 除外だけ**にし、規模は段階（中・やばい）の条件に移す。
- 新規（60 分未満）は liquidity ≥ $10K で別レーン（同齢コホート）。

## 9. 検証・較正の手順

1. **シャドー運用 3〜7 日**: 通知せず `scores` に記録（dry_run とは別のフラグ）。既存 S/M は動かしたまま。

3. **指標**: 段階ごとの precision（+50% 到達率）、現行 S/M 発火との時間差（目標 −10 分）、1 日の通知数（目標 小 30〜60 / 中 5〜15 / やばい 1〜3）。
4. **しきい値の確定**: 予算 H から逆算した分位に置き換え、重みは成分別 AUC で微調整。
5. **切替**: Tomato の GO 後に S1〜S6 を停止（M1〜M4 は残す）。`dry_run` の扱いは現行どおり。
6. 保持の拡張: リプレイのために **10 秒バケット**（活動した銘柄だけ）を 7 日、1 分バケットの 1 時間丸めを 30 日。生取引の保存はしない。

## 11. 改訂: ChatGPT 案との比較と最終形（4 レベル・100 点）

### 11.1 ChatGPT 案の要点（スクリーンショットより）

1 つの Early Momentum Score を毎ブロック更新。6 要素: 出来高加速度 30% / 参加者加速度 25% / 資金流入圧力 20% / 取引加速度 10% /
Wallet シグナル 10% / 価格反応 5%。時間軸 10 秒（超初動）・30 秒（メイン）・2 分（確認）・15 分（平常値）。
平常比は「30 秒出来高 ÷ 過去 15 分の 30 秒出来高の中央値」（平均より中央値が頑健）。時価総額で固定閾値を変えず、
Flow/Liquidity（30 秒 NetBuy ÷ 流動性）を重視。

### 11.2 論点別の判定（理由つき）

| 論点 | ChatGPT 案 | 私の案（§3〜§5） | 判定と理由 |
|---|---|---|---|
| 骨格 | 1 スコア・6 要素・100 点・毎ブロック | 加算サプライズ（案 A）・2 秒 judge | **ChatGPT の骨格を採用**。思想は同じで、6 要素×100 点の方が説明も較正も楽。更新は judge 2 秒（≒2〜3 ブロック）のままで差はない |
| 窓 | 10s / 30s / 2m / 15m | 15s / 60s / 5m + 30m / 24h | **10s/30s/2m を採用**（速い）。平常値は **15 分と 24h の両方を持ち、期待値の大きい方（厳しい方）を使う**。15 分だけだと、ポンプ開始 10 分後には自分自身が平常値になって鳴り止み、逆に一日中活発な銘柄は 24h 無しでは毎回「急増」に見える。再燃検知には 24h（将来は 7 日）が要る |
| 平常比の計算 | 30 秒出来高 ÷ 15 分中央値 | ポアソン LLR（人数）／log-MAD の z（金額） | **中央値の思想は採用、素の比は不採用**。実測: 1 分バケットで「初点火」（買い手 ≥ 5 人、直前 30 分に無し）344 件のうち **48% は直前 15 分の中央値が 0**＝比が定義できない（30 秒粒度ならもっと多い）。新規・再燃という本命のケースで壊れる。floor を入れれば動くが、その floor が結局「絶対閾値」になる。LLR/z は μ の floor を統計的に扱え、中央値/MAD の頑健性も含んでいる |
| 「加速度」の定義 | 30 秒 ÷ 平常値 = 9x を加速度と呼ぶ | 比の 30 秒差分（2 階差分） | 用語の違いだけ。比は「水準」、差分が「加速」。両方使う（比 → c_vol/c_buyers、差分 → c_accel） |
| 規模補正 | 時価総額で閾値を変えない。Flow/Liquidity | V/L（AMM 物理）＋帯別分位＋同齢コホート | **Flow/Liquidity を 20 点の主成分に採用（完全に一致。§3.3 の (1+2V/L)²−1 が理論的裏付け）**。帯別分位は **買い手数だけ**に縮小（人数には流動性の物理が無く、「30 人」の意味が規模で変わる）。新規銘柄の同齢コホートは ChatGPT 案に無いが必要（Pons が 1 日 2 万件出す Robinhood では母集団がそれしか無い） |
| 価格 | 5% | 重み減衰＋インパクト整合 | **5% で一致**。加えて価格インパクト整合 ρ（出来高のわりに動かない＝往復/wash）を減点に使う（ChatGPT 案に無い） |
| Wallet | Smart Money / KOL / 監視 Wallet 10% | 自前名簿をブロック時刻で照合 | 重み 10% は採用。**GMGN の smart カウントは銘柄あたり数分遅れる**（35 秒に 1 コール）ので、主役は自前名簿の即時照合、GMGN は補助 |
| 買い手の質 | 無し | ユニーク比・集中度・bundle・往復 | **私の案を採用**。ミームの誤検知の主因は bot 連打と bundle。1 分 buys の Fano 係数 p90 9.4 の「バースト銘柄」の相当数はこれ |
| 市場全体の補正 | 無し | マーケットファクター | 採用。BSC 全体が沸く時間帯に全銘柄が同時に鳴るのを防ぐ |
| 段階 | — | 小/中/やばい＋通知予算 | **Tomato 指定の 4 レベル固定カット（60/70/80/90）に変更**。「やばい」表記は廃止。通知予算はカットを動かすのではなく「満点の物差し」（§11.4）の較正に使う |
| 通知抑制 | 無し | クールダウン・昇格のみ・ヒステリシス | 私の案を採用（無いと HOT→STRONG→HOT の往復で連投する） |

買い手の質・自前名簿・市場補正・同齢コホート・ヒステリシス）を載せる。** どちらか一方では足りない。

### 11.3 最終形: Early Momentum Score（EMS, 0〜100）

```
EMS = 30·c_vol + 25·c_buyers + 20·c_flow + 10·c_accel + 10·c_wallet + 5·c_price − penalty

c_vol    = clip( max(z_V10, z_V30, z_V120) / 4 , 0, 1)
           z_V: log(1+買い USD) の robust z。中央値と MAD は 15 分（30 秒刻み 30 本）と 24h の 2 本から出し、
           期待値の大きい方を採用。MAD floor 0.5。z=4 で満点
c_buyers = clip( max(G_U10, G_U30, G_U120) / 4.3 , 0, 1)
           G_U: ユニーク買い手のポアソン LLR、G = sqrt(2·(k·ln(k/μ) − (k−μ)))。μ = 長窓の率 × 窓長、
           floor = max(1/長窓長, 帯 p50)。最小証拠 U_30 ≥ 3 または U_120 ≥ 5（未満なら EMS を出さない）。
           新規（60 分未満）は μ を同齢コホートの p50 から取る。G=4.3（死んでいた銘柄に 30 秒で 3 人）で満点
c_flow   = 0.7·clip( NetBuy_30s / (0.02·L) , 0, 1) + 0.3·max(BSI_120, 0)
           0.02·L = 30 秒で流動性の 2%（定積 AMM で ≈ +8% の圧力）で満点。BSI = (買−売)/(買+売)
c_accel  = clip( (G_U30(t) − G_U30(t−30s)) / 2 , 0, 1)
c_wallet = min(1, 0.4·n_listed_10m + 0.2·[Δsmart_30m ≥ 2] + 0.2·[Δholders_30m ≥ 15%] + 0.2·[visiting 30 分比 ≥ 2])
           n_listed: 自前名簿のウォレットが 10 分以内に買った件数（ブロック時刻で判定）。3 件で満点
c_price  = clip( pc_120 / 10% , 0, 1) · w_price · [ρ ≥ 0.2]      w_price = clip(100/(mcap/liq), 0.3, 1)
penalty  = 15·[U_300/B_300 < 0.3] + 10·[Top1 > 0.5] + 10·[bundle] + 20·[wash] + 10·[往復率 > 0.5] + 10·[売 ≥ 買 かつ pc_120 < 0]
           honeypot は除外。z_V・G_U はチェーン全体の z_m（買い手/分）で κ=0.5 ぶん割り引く
gate     = liquidity ≥ $20K（新規は $10K）
```

| レベル | EMS | 通知 | 同一銘柄のクールダウン |
|---|---|---|---|
| 👀 WATCH | ≥ 60 | 1 行の短文 | 30 分 |
| 🔥 HOT | ≥ 70 | 通常本文 | 1 時間 |
| 🚨 STRONG | ≥ 80 | 通常本文＋画像 | 2 時間 |
| 💥 EXTREME | ≥ 90 | 通常本文＋画像、まとめ対象外で即時 | 6 時間 |

- 昇格は即時（WATCH→HOT→…）。同レベルの再通知はクールダウン明けかつ **EMS が前回通知 +5 以上**のときだけ。降格は沈黙。
- レベルは「その銘柄の規模に対する勢い」で規模を含まない（Flow/Liquidity の思想）。規模は本文に **S / M / L バッジ**
  （流動性 < $50K / $50K〜300K / > $300K）で併記し、判断は Tomato に委ねる。

### 11.4 数値例（同じ流入の意味が規模で変わる）

| 銘柄 | 30 秒の様子 | c_vol | c_buyers | c_flow | c_accel | 合計（wallet/price 除く） |
|---|---|---|---|---|---|---|

| 流動性 $5M・平常 20 人/分 | 買い手 12 人・純買い $5K | ≈0（0） | k<μ → 0（0） | 5K/100K → 0.04（2） | 0 | **2 → 鳴らない**（「MC $10M で $5K 流入」は無視される） |

### 11.5 較正の方法（カットは動かさない）

60/70/80/90 のカットは固定。シャドー運用（§9）で 1 日の件数が目標（WATCH 30〜60 / HOT 10〜20 / STRONG 3〜8 / EXTREME 1〜3）から
外れたら、動かすのは **満点の物差し**（c_vol の「z=4」、c_buyers の「G=4.3」、c_flow の「2%」）だけ。物差しは 1 つの倍率 g で
まとめて動かし（例: g=1.2 なら z=4.8 で満点）、要素間の重みは 30/25/20/10/10/5 のまま保つ。

### 12.2 特徴量（チェーンレーン）

窓 w ∈ {10, 30, 120} 秒、評価時刻 t（判定時の現在時刻。取引ブロック時刻との差 `lag_s` も記録）:
- `B_w` 買い件数、`U_w` 別々の買い手数、`Vb_w` 買い USD、`Vs_w` 売り USD、`Net_w = Vb_w − Vs_w`、`BSI_120 = Net_120 / (Vb_120 + Vs_120)`
- 300 s: `B_300`, `U_300`, `Top1_300`（買い USD の最大 1 ウォレット比率）、`roundtrip_300`（300 s に買った人のうち 300 s 内に売った人の割合）
- 平常値（1 分バケット。窓の直前で切る＝[t−w−15 min, t−w) と [t−24 h, t−w)）:
  - 買い手レート `mu_rate`（人/分）= max(15 分平均, 24 h 平均, フロア)。フロア = max(0.5, 全体 p50)。生後 60 分未満で発射台・作成時刻が分かる銘柄はコホート p50（その生後分）を 15 分/24 h の代わりに使う（フロアはそのまま）
  - 出来高: 分次 `log(1+vol)` の中央値 `med` と MAD（MAD フロア 0.5）。中央値のフロア = log(1 + max($100, 全体 p50 出来高/分))。コホート銘柄はコホート p50 出来高/分を中央値のフロアに使う
- 市場補正: 前の 1 分のチェーン全体の買い手合計 `z_market`（24 h の分次合計の中央値/MAD、MAD フロア 1）。`G` と `z` から `κ·max(z_market, 0)` を引く（κ = 0.5）
- 名簿: 直近 10 分に買った名簿ウォレットの数 `n_listed_10m`
- four.meme 卒業前: `raised_usd` = 初見からの累計 (買い − 売り) USD、`grad_usd = 18 BNB × BNB/USD`、`progress = raised_usd / grad_usd`。作成イベントを見ていない銘柄は `raised_usd` を使わない（None）
- 判定は既存の 2 秒周期のまま（新規取引のあった銘柄だけ）。`G_U30` の 30 秒前の値は銘柄ごとに (ts, G) を 60 秒ぶん保持して取る

### 12.3 採点（§11.3 をそのまま。g = `score.gain`）

```
z_V(w)  = (log(1 + Vb_w·60/w) − med) / mad − κ·max(z_market,0)        # 分レートに換算して分次分布と比べる
G_U(w)  = sqrt(2·(k·ln(k/μ) − (k − μ)))  (k = U_w > μ = mu_rate·w/60 のとき。それ以外 0) − κ·max(z_market,0)
最低証拠: U_30 ≥ 3 または U_120 ≥ 5 を満たさなければ c_buyers = c_accel = 0
c_vol    = clip(max_w z_V(w) / (4·g), 0, 1)
c_buyers = clip(max_w G_U(w) / (4.3·g), 0, 1)
c_flow   = 0.7·clip(Net_30 / (0.02·g·L), 0, 1) + 0.3·max(BSI_120, 0)         # L = 流動性 USD
           four.meme 卒業前（L 不明・progress < 1）: 0.7·clip(Net_30 / (0.05·g·grad_usd), 0, 1) + 0.3·max(BSI_120, 0)
           L も raised_usd も無い: 0.3·max(BSI_120, 0) のみ
c_accel  = clip((G_U30(t) − G_U30(t−30 s)) / 2, 0, 1)
c_wallet = min(1, 0.4·n_listed_10m + 0.2·[Δsmart_30m ≥ 2] + 0.2·[Δholders_30m ≥ 15%] + 0.2·[visiting 30 分比 ≥ 2])   # 後ろ 3 つは既存 S4/S5/S6 の計算を流用
c_price  = clip(pc_120 / 10%, 0, 1) · w_price · [Net_120 > 0]、w_price = clip(100 / (mcap/L), 0.3, 1)（L 不明なら 1）
penalty  = 15·[B_300 ≥ 10 かつ U_300/B_300 < 0.3] + 10·[B_300 ≥ 3 かつ Top1_300 > 0.5] + 10·[bundle]
         + 20·[wash（GMGN スナップショットの wash フラグ）] + 10·[roundtrip_300 > 0.5] + 10·[Vs_120 ≥ Vb_120 かつ pc_120 < 0]
bundle   = 初見から 3 ブロック（ブロック時刻の異なる最初の 3 つ）のどれかに別々の買い手 ≥ 5。付いたら 30 分維持
EMS      = 30·c_vol + 25·c_buyers + 20·c_flow + 10·c_accel + 10·c_wallet + 5·c_price − penalty（0〜100 に clip）
除外     = honeypot（スナップショットに印）→ 点数 0・理由を記録。ゲート: L ≥ $20K（生後 60 分未満は $10K）。
           four.meme 卒業前はゲートを「U_120 ≥ 5 かつ bundle でない」に置き換える
レベル   = ≥60 WATCH / ≥70 HOT / ≥80 STRONG / ≥90 EXTREME（`score.levels`。カットは動かさない。調整は g だけ）
```

### 12.4 通知（ヒステリシス・クールダウン・予算）

- 銘柄ごとの状態 `score_state`（chain, address, last_level, last_score, last_notify_ts）を SQLite に持つ（再起動で通知が再発しないため）
- 送る条件: レベル ≥ WATCH かつ（`level > last_level`、または `level == last_level` かつ `now − last_notify_ts ≥ cooldown[level]` かつ `score ≥ last_score + 5`）
- クールダウン: WATCH 30 分 / HOT 60 分 / STRONG 120 分 / EXTREME 360 分
- 予算（超えたら送らず `suppressed=budget` で記録）: 1 時間 WATCH 6 / HOT 3 / STRONG 2 / EXTREME 1、1 日 60 / 20 / 8 / 3。`scores` の notified 行を数える

### 12.6 API レーン（robinhood / arc）の簡易スコア

5 分集計しか無いので窓は 5 分のみ。`U = buyers5m`, `B = buys5m`, `Vb ≈ vol5m·buys/(buys+sells)`, `Vs` 同様。平常値はスナップショット履歴
（15 分 / 24 h）の分レート。`c_flow = 0.7·clip(Net_5m / (0.05·g·L)) + 0.3·BSI`。`c_accel` は前スナップショットとの G の差 / 2。
名簿は使えないので `c_wallet` は Δsmart / Δholders / visiting だけ。bsc はチェーンレーンが採点するので API レーンでは採点しない
（`score.api_chains = ["robinhood", "arc"]`）。
